Questions,
answered.

The short version: Docklet is local-first, Docker-managed, and happiest in the tray.

Do I need Docker Desktop?

Yes. Docklet uses the Docker CLI and expects Docker Desktop to be running with Linux containers. If Docker is offline, Docklet can help you launch it.

Where does my data live?

Service data lives in named Docker volumes. Stopping a service preserves both the container and its volume. Reset or Remove is destructive, and only affects resources Docklet created.

Can I use my own Docker image?

Yes. Custom services support one image, one localhost port, an optional named volume, environment variables, and a health command. Docklet does not use Compose, bind mounts, privileged mode, or host networking.

Which local models can I run?

The curated GGUF catalog covers small chat, coding, and reasoning models. You can also add a custom GGUF from Hugging Face. The bundled engine is a CPU-only llama.cpp build for Windows x64.

How do I quit Docklet completely?

Use Quit in the tray menu. Closing the main window or the quick panel only hides it; Docklet and your running services stay available in the tray.
